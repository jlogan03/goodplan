# Test Audit — 2026-03-27

## Overall Assessment

The test suite is well-structured with 93 test files across unit (60), integration (14), and fitness (9) categories. State machine tests are excellent — every transition handler has both happy-path and error-path coverage with zero mocking. The main weaknesses are: a cluster of recently-added files without direct tests (helpers.ts, serialize.ts, markdown-files.ts), stale test data (event count hardcoded at 38 vs actual 41, fixtures missing tasks/ directory), and missing fitness functions for 2 of 7 documented invariants.

## Coverage Gap Findings

### Finding 1: `transitions/helpers.ts` — zero direct tests (CRITICAL)
617 lines of pure functions: `evaluateRefinement()` (circuit breaker), `guardEpicStatus()`/`guardSliceStatus()`/`guardQuestStatus()`, `processLearnings()` (rollup), `appendActivityLog()`, entity builders. Edge cases in refinement evaluation and learnings rollup are untested.

### Finding 2: `data/serialize.ts` — no unit test (CRITICAL)
Public API contract for `goodplan state` output. Handles 4 entry types, `inline` option for markdown. Only tested indirectly via state command tests.

### Finding 4: `data/markdown-files.ts` — zero tests (IMPORTANT)
`writeMarkdownFiles()` and `copyMarkdownFiles()` with atomic write pattern. Bug here silently corrupts learnings data.

### Finding 7: `schemas/commands/` — no dedicated tests (IMPORTANT)
8 Zod validation files are the first line of defense against invalid input. Only tested indirectly through command integration.

### Finding 11: `rpc/types.ts` runtime helpers (MINOR)
`resolveEntityName()` and `resolveEntityJsonPath()` — exhaustive switch functions, untested.

## Stale Test Findings

### Finding 3: 53 integration/fitness tests failing (CRITICAL)
All tests that spawn the compiled binary against fixtures get exit code 2. Unit tests (899) all pass. Likely related to recent changes on quest-completions branch.

### Finding 5: Hardcoded event type count (IMPORTANT)
`state-events.test.ts` asserts 38 events but code has 41 (missing CREATE_TASK, DROP_TASK, CONVERT_TASK). Self-referential check — doesn't catch drift.

### Finding 6: Test fixtures missing `tasks/` (IMPORTANT)
All fixtures lack `tasks/overview.json` but current `INIT_PROJECT` creates it. Fixtures represent stale schema shape.

## Quality Findings

### Finding 9: `process.chdir()` coupling (IMPORTANT)
11 command test files mutate global process state. Risk of test pollution in parallel execution.

### Finding 10: Source-string fitness tests (IMPORTANT)
`atomic-writes.test.ts` asserts source code contains specific string patterns. Breaks on any refactoring even if behavior preserved.

### Finding 12: `toBeDefined()` guard pattern (MINOR)
188 occurrences used as type-narrowing before `!` assertions. Redundant — subsequent assertions would fail more clearly.

### Finding 13: Command test boilerplate duplication (MINOR)
11 files duplicate identical setup/teardown and command runner patterns.

### Finding 15: Busy-wait timing (MINOR)
`commit.test.ts` uses 50ms busy-wait for mtime resolution. Classic flaky test pattern.

## Strategy Findings

### Finding 8: No INV-007 fitness function (IMPORTANT)
INV-007 ("structured error responses with correct exit codes") explicitly lists a fitness function candidate but none exists.

### Finding 14: No INV-001 fitness function (MINOR)
INV-001 ("every mutation through state machine") suggests static import analysis but no fitness test exists.

### Strategy notes
- Test pyramid ratio (adjusted for command tests being integration-level): ~48 unit / 26 integration / 9 fitness — healthy for a CLI tool
- State machine has excellent coverage (23 test files, all transitions tested)
- Zero `vi.mock` usage — no filesystem mocks per convention — excellent practice
- Fitness functions protect 5 of 7 invariants (missing INV-001, INV-007)
