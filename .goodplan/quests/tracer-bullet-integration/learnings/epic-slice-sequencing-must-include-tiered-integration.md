The original v2 epic sequenced 12 slices bottom-up (engine → trust → commands → skills → migration/dogfood) with all integration testing deferred to slice 12. This creates high risk of discovering mismatches at layer boundaries late in the project. The fix: embed verification tier requirements directly in each slice goal so plan-phase agents include appropriate integration tests. Tiered verification: engine (unit+smoke), trust (unit+CLI binary), commands (CLI binary via Bun.spawnSync), skills (Agent SDK harness), capstone (full E2E). Key insight: creating a new reviewer agent in the repo source would not help during the current epic since the installed plugin runs the old version — instead embed requirements in slice goals where plan-phase agents read them.
