## Staleness Findings

### Finding 5: Fitness functions marked "candidate — not yet written" in per-API docs
All 9 fitness function tests exist in `tests/fitness/` and are correctly listed in `_overview.md`, but `state-machine-api.md`, `data-layer-api.md`, `commands-api.md`, and `rpc-layer-api.md` still say "candidate — not yet written."

### Finding 6: `CREATE_QUEST` event missing `goal` field
`state-machine-api.md` shows `{ type: 'CREATE_QUEST'; name: string; ts: string }` but code requires `goal: string`.

### Finding 8: `conventions.md` skills listing incomplete
Missing `audit-docs/`, `audit-tests/`, `capture/` from the 14-skill listing (actual: 18 skills).

### Finding 9: `conventions.md` repo structure stale entries
Lists `src/core/workflow/` (doesn't exist) and `src/commands/activity/` (not implemented).

### Finding 10: `COMPLETE_QUEST`/`COMPLETE_SLICE` event type names
Docs show `Learning[]` / `ArchitectureDelta[]` but code uses `LearningEventEntry[]` / `ArchitectureDeltaInput[]`.

### Finding 11: `flows.md` tracer bullet note
Line 34 contains historical development note about "tracer bullet init" that's no longer relevant.

## Gap Findings

### Finding 2: Task namespace entirely missing from `commands-api.md`
5 commands (`task:create`, `task:list`, `task:show`, `task:drop`, `task:convert`) are fully implemented but have zero documentation.

### Finding 3: Task events missing from `state-machine-api.md`
`CREATE_TASK`, `DROP_TASK`, `CONVERT_TASK` events are defined in code and documented in `transition-tables.md` but absent from the `StateEvent` union.

### Finding 4: Task events missing from `rpc-layer-api.md`
`create-task`, `drop-task`, `convert-task` BeginPhase values are handled in `begin.ts` but not in the BeginPhase type documentation.

### Finding 12: Context module has no dedicated architecture doc
`src/core/context/` (7 files) is a peer subsystem in `_overview.md` but has no `context-api.md`.

### Finding 13: `data-model.md` schema registry missing task patterns
`tasks/overview.json` and `tasks/<name>/task.json` patterns exist in code but not in docs.

## Consistency Findings

### Finding 1: `docs/primer.md` directory structure contradicts `data-model.md`
- Shows flat `slices/` (should be nested under epics)
- Shows separate `goal.md` files (goals are JSON fields)
- Shows `learnings.md` (should be `learnings.jsonl` + `learnings/` dir)
- Shows `tasks/task.jsonl` (should be per-task directories)

### Finding 5: Schema registry examples use flat paths
`data-layer-api.md` and `data-model.md` show `/^slices\/[^/]+\/slice\.json$/` but code uses `/^epics\/[^/]+\/slices\/[^/]+\/slice\.json$/`.
