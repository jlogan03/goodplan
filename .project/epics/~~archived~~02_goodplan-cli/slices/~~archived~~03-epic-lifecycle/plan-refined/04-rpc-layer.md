### Tasks

- [x] Create `src/core/rpc/begin.ts` — `begin<P extends BeginPhase>(phase: P, target: Target, payload: BeginPayloadMap[P], options?: WorkflowOptions): BeginResult`. Pattern: loadState → build StateEvent from (phase, target, payload) mapping → reduce → check isStateError → commitState → return BeginResult. Event mapping follows rpc-layer-api.md explicitly (e.g., begin('create', {type:'epic'}) → CREATE_EPIC, begin('explore', {type:'epic'}) → BEGIN_EXPLORE). **In-scope BeginPhase values:** `create` (epic only), `explore`, `define-architecture`, `refine-architecture`, `define-slices`, `refine-slices`, `activate`, `abandon` (epic only), `add-verification`, `update-verification`. Out-of-scope values (`plan`, `refine-plan`, `implement`, `update-decision`, `rollup`, and `create`/`abandon` for slice/quest/decision targets) throw "not yet implemented." Inject `ts: new Date().toISOString()` only on events that carry a `ts` field per state-machine-api.md (CREATE_EPIC, ACTIVATE_EPIC), not universally. **Payload forwarding:** `begin()` must accept a typed `payload` parameter (typed per BeginPhase via the `BeginPayloadMap` defined in types.ts) to carry event-specific data that cannot be derived from phase+target alone. Required for: `ABANDON_EPIC` (needs `reason`), `ADD_VERIFICATION` (needs `verification`), `UPDATE_VERIFICATION` (needs `index` + `verification`). The payload fields are spread into the constructed StateEvent.
- [x] Create `src/core/rpc/complete.ts` — `complete(target: Target, input: CompleteInput, options?: WorkflowOptions): CompleteResult`. Same pattern. Maps to COMPLETE_EPIC based on `target.type` (not `input.type`). Only epic completion is in scope for this slice — slice/quest completion branches should throw "not yet implemented" (deferred to slices 04-05). Constructs the COMPLETE_EPIC event with verificationResults from input.
- [x] Create `src/core/rpc/submit.ts` — `submit(phase: SubmitPhase, target: Target, content: SubmitInput, options?: WorkflowOptions): SubmitResult`. **Note:** the `phase` parameter and `SubmitInput.phase` field are intentionally redundant — the top-level `phase` parameter drives event mapping, while `SubmitInput.phase` is the discriminant for the content union (determines which payload fields are present). This redundancy is intentional (do not "fix" it by removing one). They must match; assert with `INTERNAL_ERROR` (not a user-facing validation error) since both values are constructed by the CLI — a mismatch indicates an internal consistency failure. Phase+target-to-event mapping per rpc-layer-api.md: `submit('plan', {type:'slice'}) → COMPLETE_PLAN`, `submit('plan', {type:'quest'}) → COMPLETE_QUEST_PLAN`, `submit('refinement', {type:'slice'}) → COMPLETE_REFINEMENT_ROUND`, `submit('refinement', {type:'quest'}) → COMPLETE_QUEST_REFINEMENT_ROUND`, `submit('implementation', {type:'slice'}) → COMPLETE_IMPLEMENTATION`, `submit('implementation', {type:'quest'}) → COMPLETE_QUEST_IMPLEMENTATION`, `submit('explore', {type:'epic'}) → COMPLETE_EXPLORE`, `submit('architecture', {type:'epic'}) → COMPLETE_ARCHITECTURE`, `submit('slices', {type:'epic'}) → COMPLETE_SLICING`, `submit('refine-architecture', {type:'epic'}) → COMPLETE_REFINE_ARCHITECTURE`, `submit('refine-slices', {type:'epic'}) → COMPLETE_REFINE_SLICES`. For refinement phases: passes scores from SubmitInput and override from WorkflowOptions.
- [x] Create `src/core/rpc/types.ts` — centralized RPC types: BeginPhase, SubmitPhase, Target, WorkflowOptions, BeginResult, CompleteResult, SubmitResult, CompleteInput, SubmitInput. Define these per rpc-layer-api.md. **Payload type safety:** the `payload` parameter on `begin()` should be typed per BeginPhase using a discriminated union or mapped type (e.g., `BeginPayloadMap` mapping phase to payload shape), not `Record<string, unknown>`. At minimum: `abandon` → `{ reason: string }`, `add-verification` → `{ verification: Verification }`, `update-verification` → `{ index: number; verification: Verification }`, `create` (epic) → `{ name: string; goal: string }`. No-payload phases map to `Record<string, never>` (empty object `{}`), NOT `undefined` — with `exactOptionalPropertyTypes: true`, an `undefined` payload cannot be passed explicitly as a positional parameter and cannot be omitted when it's required. Using `Record<string, never>` means callers pass `{}` for no-payload phases (e.g., `begin('explore', target, {})`), which is ergonomic and type-safe. This preserves compile-time type safety for event-specific data.
- [x] Refactor `src/core/rpc/init.ts` — make rpcInit route through `begin('create', {type:'project'}, ...)` internally, or replace it entirely. Update init command to call `begin` directly.
- [x] Update all RPC functions (`begin`, `complete`, `submit`, and refactored `rpcInit`) to use `loadState()` instead of `assembleState()` for all state reads. The existing `rpcInit()` calls `assembleState()` directly — this must switch to `loadState()` after Phase 2.
