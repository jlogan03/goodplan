# Plan: Onboard Repo

## Confirmed Goal

Build an `/onboard-repo` skill (SKILL.md + reference files under `skills/onboard-repo/`) that scans an existing repo with code but no `.project/` and scaffolds a complete `.project/` directory. Extracts conventions, architecture, subsystem maturity, in-flight migrations, tech debt, expertise profiles, and hot spots from repo artifacts (README, git history, code structure, config files, `gh` CLI). Only asks the user about things that can't be inferred. Uses existing CLI commands — no CLI or core modifications.

Additionally, the skill should seed the workflow's ongoing expertise tracking system by analyzing the user's git commits and PR comments to build an initial expertise profile that can be updated over time.

Verified via automated test harness using Anthropic Claude SDK on a synthetic fixture repo (generated by script), and smoke-tested on a real open-source repo.

## Overview

Build an `/onboard-repo` skill that brings existing repos (with code but no `.project/`) into the goodplan workflow. The skill extracts information from the repo itself — README, code structure, git history, config files, PR comments — rather than making the user re-explain everything. Only asks about things that can't be inferred.

**Core flow**: Pre-flight checks → scan repo → scaffold `.project/` via `goodplan init` → generate idea.md → detect conventions → extract architecture & subsystems → estimate maturity → interview user for validation → detect migrations & debt → create side quests → profile expertise → identify hot spots → update CLAUDE.md → present summary → optionally create first epic.

**Step map**: Step 0: version check, Step 1: pre-flight, Step 2: scan, Step 3: init, Step 4: idea.md, Step 5: conventions.md, Step 6: architecture extraction, Step 7: architecture interview, Step 8: migration detection, Step 9: side quest creation, Step 10: expertise profiling, Step 11: hot spots, Step 12: CLAUDE.md update + summary.

**Data sources**: Local git history (always available) + `gh` CLI for PR comments/reviews (when authenticated, graceful fallback to git-only).

**Verification approach**: Automated tests using Anthropic Claude SDK test harness — starts a session on a script-generated fixture directory and invokes the skill. Fixture repo generated by `scripts/generate-onboard-fixture.sh` (not checked in as a nested git repo). Smoke-tested on a real open-source repo. **Known test limitation**: the fixture has no GitHub remote, so `gh` CLI commands (PR conventions, expertise PR analysis) will fail in automated tests — these are only verified in the real repo smoke test.

**Shared references**: SKILL.md uses `../_shared/references/cli-interaction.md` (loaded at Step 0 — error handling, re-entry), `../_shared/references/expertise-tracking.md` (loaded at Step 10 — two-layer expertise protocol), and `../_shared/references/output-templates.md` (loaded at Step 12 — Variant B done summary). References loaded on demand at point of use to conserve context.

**Re-entry handling**: Each step detects already-completed work and skips or offers re-detection (per `cli-interaction.md` section 10). Partial failure at any point allows resumption. **Error recovery**: on step failure, retry once, then inform user and continue with degraded output (matching `/create-architecture`'s pattern). Non-critical steps (expertise profiling, hot spots) degrade gracefully; critical steps (init, idea.md) halt and report.

**Progressive disclosure**: SKILL.md contains the step flow with pointers to reference files. Heuristic details live in `references/` files, not inline in SKILL.md.

Skills-only changes — new SKILL.md + reference files under `skills/onboard-repo/`, plus install script update.
